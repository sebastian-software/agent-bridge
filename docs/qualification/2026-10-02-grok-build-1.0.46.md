# Grok Build 1.0.46 live qualification record

**Date:** 2026-10-02

**Status:** Qualified for one-shot delegation with the default login

This record covers the Grok ACP adapter on Grok Build 1.0.46. It does not cover
steering, continuation, or general questions, which the adapter does not
advertise. Two separately authenticated accounts were not available; named
contexts were exercised with the default `GROK_HOME` and with an empty one.

| Item    | Value                                                                 |

| Relay   | Source build of `main` at `e28402e` plus this change, Node.js 24.21.0 |
| Harness | Grok Build 1.0.46 (`grok agent --no-leader stdio`, ACP v1)            |
| Account | Default `~/.grok`, logged in with grok.com                            |

## What the first live run found

Before this change the adapter failed every live invocation:

- Grok sends `session/update` (`available_commands_update`) before the
  `session/new` response carries the session ID, which the adapter rejected as
  malformed.
- `--model`, `--always-approve`, and `--permission-mode` before the `agent`
  subcommand have no effect in ACP mode. A run requested for `grok-4.5`
  reported `grok-4.7`, and both permission flags still produced
  `session/request_permission`.
- Grok runs each tool command in its own process group. After cancellation or
  timeout, the tool shell and its `sleep` kept running with init as parent.

## Native evidence

- `grok models` printed `You are logged in with grok.com.` and the models
  `grok-4.7`, `grok-4.7-build-fast`, `grok-4.6`, and `grok-4.5`. With an empty
  `GROK_HOME` it printed `You are not authenticated.`
- ACP `session/set_model` answered `{"Ok": "grok-4.5"}`, Grok emitted
  `model_changed`, and the prompt result reported `modelId: "grok-4.5"`.
- `agent --reasoning-effort low` produced `reasoning_effort: "low"` in
  `model_changed`.
- `agent --always-approve` let Grok write a file. Without it, Grok asked with
  `session/request_permission`; selecting `reject-once` failed the tool call,
  wrote nothing, and ended the turn with `stopReason: "cancelled"`.
- ACP `session/cancel` during a running `sleep` stopped the tool within 40 ms
  and ended the turn with `stopReason: "cancelled"`.

## Deterministic coverage

`test/grok-adapter.test.ts` mirrors the 1.0.46 protocol: early session updates,
the model list in `session/new`, `session/set_model`, and `_meta` usage. It
covers discovery from `grok models`, rejection of unavailable, unconfirmed, or
substituted models, the reject answer under `deny`, the refusal under
`unattended`, and cancellation of a tool that ignores SIGINT and SIGTERM in its
own process group. Before the fix, that last test failed with the tool still
running.
